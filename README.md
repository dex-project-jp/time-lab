# TIME LAB v0.1

iPhone Safariを主対象にした、紙タイムカードの端末内OCR・月間勤怠集計PWAです。
公開先: https://dex-project-jp.github.io/time-lab/
リポジトリ: https://github.com/dex-project-jp/time-lab
既存アプリには変更を加えていません。

## 起動

リポジトリのルートが配信用フォルダです。ビルドや有料APIは不要です。

ローカル確認: `python3 -m http.server 8080`
PCのブラウザで `http://localhost:8080` を開きます。
iPhoneでのPWA・オフライン動作にはHTTPSの配信先が必要です。ファイルを直接開く方法は非対応です。
GitHub Pages: mainブランチ / (root) から配信します。

## 使い方

1. 従業員名・対象月・集計方式を指定。時給制では時給を入力。
2. 前半・後半の画像を選ぶ。iPhoneではカメラを起動できます。
3. 表の枠、傾き、日付＋4打刻列の境界を確認してOCR実行。
4. 「確認候補として取り込む」で月へ統合。既存の入力は上書きしません。
5. 日別一覧で画像・OCR原値を照合し、時刻や午前午後の出勤を修正。
6. 休みも含め、各日を確認済みにします。未確認・矛盾のある日は集計から除外。
7. CSV出力、JSONバックアップ・復元。

日付は対象月の日別欄で修正できます。誤った日に取り込んだ値は、正しい日へ手入力し、元の日の値・出勤チェックを修正してください。OCR原値は履歴として残ります。

## 集計

- 日給月給: 午前午後とも出勤で1日、どちらかで0.5日。賃金は計算しません。
- 時給: 午前・午後の各出退勤の差を1分単位で合計。月の合計だけを15分単位に切り上げ。
- 例: 月合計6時間55分 → 給与計算用7時間。時給1200円なら基本賃金8400円。
- 小数円が発生する基本賃金の表示は1円に四捨五入。
- 月ごとの集計方式・時給を保持。端末内記録では、OCR原値、手動修正時刻、計算結果を別の項目に保存。
- 深夜・残業・休日の割増、税・社会保険は未実装。給与確定額ではありません。
- 日付をまたぐ勤務は要確認となります。v0.1は同日の午前午後2勤務を対象にしています。

## OCRの範囲と限界

MAX ER-Sのような日付＋4打刻の表を想定した試作品です。機種全般への対応・認識精度は保証していません。
表の罫線投影から範囲を仮検出し、回転・切り抜き・白黒補正後にTesseract.js 6.0.1で数字と時刻を認識します。
台形の遠近補正や手書き専用認識は未実装。真上からの撮影を推奨します。
実カードの印字・罫線・空欄状態によって表範囲や列の調整、手入力が必要です。
日付が読めない行は取り込まず、日付や時刻を推測で埋めません。空欄と未認識は自動確定せず、すべて要確認です。
信頼度85%未満・不正時刻・重複日付・前後半の範囲外を要確認にします。OCR文字と信頼度を保持します。
同一画像の再登録と既存日付の上書きを防ぎます。別角度で撮った同じカードは画像一致判定できませんが、日付の既存値を上書きしません。

「OCRテスト」で任意画像、または生成した3行のサンプルを試せます。テストは勤怠へ反映しません。
CHAI LABのソースは接続先で404だったため参照できていません。画像処理は独自実装です。

## 保存とプライバシー

IndexedDBに従業員・年月単位で記録。撮影画像は最大辺2200pxのJPEGとして保存します。
オリジナル写真のファイルは変更しません。保存されるのは照合用に縮小した画像です。
画像・勤怠を送るAPI、解析サーバー、アクセス解析、広告はありません。
OCR本体・Worker・WASM・英語数字モデルをvendorに同梱し、実行時の外部CDNを使いません。
Service Workerは初回に約18MBを同一配信元からキャッシュします。初回読み込み完了後の再訪からオフライン利用できます。
Safariのサイトデータ削除やOSによる領域回収、配信URLの変更ではデータが失われたり別の保存領域になります。
バックアップJSONは画像・個人情報を含む平文です。端末変更やURL変更の前に保存してください。
復元は既存全データの置き換えです。確認ダイアログが表示されます。

## v0.3 (2026-11-10)

### 取り込み
ImportCoreの同じ仕様から依頼文を生成し、month/rows/日付/4時刻/am/pmを項目別に検証します。monthはYYYY-MMが標準。year+数値month、targetMonth、days/records、日付の数字文字列、コード枠や前後の説明を含む貼付けも受理します。前後の説明は単一JSONだけを切り出し、複数コード枠は拒否。totalDays/verifiedは確定根拠にしません。月が違うと両方の月と修正方法を表示。明示操作で元の月を保持したまま写真を正しい月へコピーします。Sカードの「前半」印刷と16〜31日の記録の組合せに対応し、登録区分より各行の日付を優先。写真の日付不明行を推測しません。
一括取り込みは空いている日のみ。再取り込みは既存打刻と原値を保護。採用は候補に限り、写真照合・日別確認が必須です。

### SカードOCR（試験機能・任意選択）
青罫線の周期から16行の仮枠を提案。四隅は数値で修正可能。射影変換、局所背景補正、ドット印字の線補強、セル別OCRを追加。Sカード用の4打刻列と時間数領域を分離。既定は従来OCRを維持。自動枠・行数・列境界は写真で照合してください。15行などでは行数の手動調整が必要です。
日付のOCRが失敗した場合、最初の日を選び、利用者が行の並びを確認したチェックを入れた場合のみ行順を日付に対応づけます。この操作なしに未知の日付を推測して埋めることはありません。手書き・重ね打刻の正確な自動認識は未達。結果はすべて未確認候補です。

### 検証の限界
提供された実写真で、印字が比較的読める41セルを目視転記した暫定参照と比較しました。利用者による日別照合・承認が未取得なので、これを確定した正解率とは呼びません。従来自動枠は0/41一致、Sカード補正の全自動は1/41一致、日付行順を手動確認する条件では4/41一致（未読33、不一致4）。この単一写真の暫定測定では実用精度に達していません。写真の正解をOCRに埋め込んで一致させる処理はありません。一般化した精度、手書き対応、iPhone実機での精度は保証できません。実カード・氏名・参照時刻は公開リポジトリに含めません。

### 正解データ
日別欄で修正して確認済みにした非空の打刻セルだけを、その日のsourceIdsの写真へ紐づけて端末内保存。編集・確認解除で無効化。空欄は未読との区別がつかないため分母から除外します。訂正データはモデルの自動再学習ではなく、将来の改善とセル単位評価の資料です。検証用出力は氏名欄・年月・ファイル名・ID・メモを除いたセル画像と時刻だけ。画像プレビューを目視確認してから保存し、自動送信はしません。

### 保存と既存機能
DB名/バージョン/ストア/キーとバックアップversion:1は維持。任意フィールドを画像内に追加するだけです。既存の月間集計・日給月給・時給・給与明細・印刷/PDFのコードは変更していません。

## v0.5.5 日本語表の取り込みと写真セット

通常の操作は、給与対象月と従業員選択→前半/後半写真を撮影・選択→ChatGPTで読み取る→日本語表を丸ごと貼付→日付と4時刻を編集・写真照合→保存。解析依頼文も日本語表の共通仕様へ変更。JSON編集を要求しない。旧JSON経路は詳細テストに維持。

表は日付/午前出勤/午前退勤/午後出勤/午後退勤の5列、日付はYYYY-MM-DD。Markdown、タブ区切り、コード枠、全角数字、一部の縦並びコピーを受理する。不明は空欄。年や月のない日付は給与対象月から推測せず、具体的なエラーを表示する。氏名・給与期間外・実在日・重複・時刻を検証し、既存の日付は保護する。確認前の値は給与に使わない。片方の打刻だけの行は未確認のまま保存できるが、確認済みにできない。

公開版で実施した操作：複数日をクリップボードから貼り付け、退勤を修正、確認して保存。期間合計415分→420分、時給1200円で8400円。再読み込み後の保持と、再取り込み新規0/既存2日保護を確認。実カードの利用者確認済み2日分（一部のみ）も表として読み取り、完全な1日だけを確認して454分→465分、9300円。不完全な日は未確認で除外。既存v0.4確認用の375分/7500円も保持。これは取り込み試験であり、全カードを正しく解析できるという精度測定ではない。

前半1〜15日は給与対象月、後半16日〜月末は前月の写真枠へ登録。撮影と既存写真選択を分離。同じ従業員・給与対象月の写真選択だけを任意のphotoSetsへ保存し、既存のmonths/images/rowsを移動しない。写真と解析表の対応付けも保持。写真は端末内、外部へ自動送信しない。1〜2枚のFileと依頼文をWeb Shareへ渡す。共有非対応または添付されない場合、写真を1枚ずつ保存/長押し保存し、ChatGPTの＋から手動添付して依頼文を貼り付ける。iPhone Safari/PWAやChatGPTアプリが実際に写真を受信したかは未確認。

四隅・OCR原文・認識率比較・匿名出力は「詳細テスト」に維持。今回のOCR認識アルゴリズムは変更しておらず、新たな精度向上は主張しない。自動学習も未実装。

従来129項目に、table-tests.cjs（21）とtable-flow-tests.cjs（8）を追加。計158項目。DB time-lab/version1/data/state、バックアップversion1、15日締め、日給月給、期間合算後15分切上げを維持。変更前main完全バックアップ：time-lab-v05-before-table-import.zip（61a500623abd775741395a421bc5b73d5999701a）。


## v0.6 勤怠集計・日別一覧

日給月給・時給の双方で、確認済みの出勤換算日数、実出勤日数、午前・午後回数、実働分を独立計算する。給与計算用時間は期間全体を合算後、一度だけ15分切り上げる。確認待ち、読取不明、打刻不足・矛盾だけを要確認とし、未入力・将来未入力をエラー件数に入れない。未確認の参考値と確定集計は別表示。日給月給の時刻なし出勤記録は従来どおり日数へ反映し、実働不明と表示する。時給方式では時刻不足を除外する。

保存後・給与画面上部に従業員、15日締め期間、日数・回数・時間・要確認を表示。通常は5列のコンパクトな時刻表示と状態のみ。日付をタップした日だけ編集する。写真照合済みのチェック後に保存し、履歴と元の解析文字を保持。従来の未確認データも保存済み一覧から確認できる。同じ値の再取り込みで明示的に確認した場合のみ、既存打刻を変えず確認状態を更新できる。異なる値は上書きしない。

ChatGPT依頼文は、概要→コピー専用コードブロック→確認事項の3部構成を指定。コピー部分は YYYY-MM-DD HH:MM HH:MM HH:MM HH:MM、空欄/不明は - 。見出し・説明・氏名を混ぜない。スペース/タブ/全角、改行、コード枠、旧日本語表、旧JSONを受理。ChatGPTのUIを変更する機能や自動返送ではない。

公開画面で、コピー専用の2日分→編集・確認・保存→415分/420分/8400円、出勤換算1日・午前2回を確認。日付タップの編集で416分へ即時更新し、元の415分に戻して再読み込み保持。旧日本語表で既存2日を保護し、A4明細でも日数・時間・8400円を確認した。実カードの承認済み1日は213+241=454分、出勤1日・午前1回・午後1回、給与465分。別の打刻不足1日だけ要確認。残りの未入力を要確認に数えない。これは承認済み部分のみの検証であり、カード全行の確定やOCR精度改善を意味しない。

従来158項目＋v06-tests.cjsの19項目、計177項目。responsive-check.htmlでは375px iframeのChrome表示を確認。iPhone Safari/PWA実機、写真共有受信、PDF送信は未確認。OCRの大規模改修・自動学習は行わない。DB/バックアップversion1、従業員別・15日締め、写真2枚、旧明細、共有、既存OCR比較を維持。変更前コードZIPと保存データJSONを取得済み。写真・氏名・実打刻データはリポジトリに含めない。
